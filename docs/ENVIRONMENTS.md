# Environment matrix

The backend reads only environment variables (`backend/icp_api/settings.py`).

- **Local.** `.env` is loaded only when `APP_ENV` is unset or `local`. Real environment variables
  always win.
- **Staging and production.** Configuration is validated strictly at startup, and the process refuses
  to start if any rule is violated (see the last table).

Two deployed topologies are supported by the same code; the zero-cost one (docs/DEPLOYMENT.md) is
the default for staging: since 2026-10-28 its backend is a serverless function on Vercel Hobby
(`backend/icp_api/serverless.py`, entry `infra/vercel/index.py`). The paid-tier columns (D1 REST + R2 +
Postgres/MLflow) remain valid, and the Docker image still serves any container host (and the laptop
Quick Tunnel fallback).

## Deployed-configuration validation (enforced at startup)

| Rule | Reason |
|---|---|
| `METADATA_BACKEND` is `d1_gateway` (with `GATEWAY_INTERNAL_URL`) or `d1` (with `D1_*`) | deployment filesystems are not persistent |
| `OBJECT_STORE_BACKEND` is `gateway` (with `GATEWAY_INTERNAL_URL`) or `s3` (endpoint, bucket, keys) | same |
| `MODEL_SOURCE=bundle`, or `MODEL_SOURCE=mlflow` with a non-SQLite `MLFLOW_TRACKING_URI` and an `s3://` `MLFLOW_ARTIFACT_ROOT` | the served model must survive redeploys: either an exported bundle in the object store or a persistent registry |
| `GATEWAY_SHARED_SECRET` ≥ 32 chars whenever the gateway data plane is used (any env) | the data plane is authenticated by this secret alone |
| every `GATEWAY_ACCEPTED_SECRETS` entry ≥ 32 chars | a previous secret accepted during rotation must be as strong as the current one |
| `API_HOST` set to a non-loopback address (not for the serverless entry, which binds nothing) | a loopback bind is unreachable on a container host; the code has no wildcard default |
| `REQUIRE_GATEWAY_SECRET=true` with a secret of ≥ 32 chars | the backend must not be directly usable |
| each admin token ≥ 32 chars | brute-force resistance |
| `CORS_ALLOWED_ORIGINS` has no `*` | no wildcard CORS |
| `LOGIN_ACCOUNT_FAILURES_MAX` ≥ `LOGIN_FAILURES_MAX` | the account-wide sign-in ceiling must not be stricter than the per-IP pause |
| `API_INSTANCES` = 1 (any env; `icp-api serve` also always runs one uvicorn worker) | rate limits and sign-in counters are per process |
| `AUDIT_RETENTION_DAYS` ≥ 0 (any env) | 0 keeps every audit row |
| `PUBLIC_HISTORY_MONTHS` between 0 and 36 (any env) | the public snapshot shows recent context, not the archive (full history is a signed-in feature) |

## Security and limit settings (backend)

| Variable | Default | Meaning |
|---|---|---|
| `REQUEST_TIMEOUT_SECONDS` | 30 | Time budget of one API request: the middleware answers `504 REQUEST_TIMEOUT` when it is used up, and the data-plane clients (D1 and KV through the Worker) start no read, no retry and no back-off after it (a write's first attempt still starts, so a write sequence is never cut in the middle); durations and the full budget in [OPERATIONS.md](OPERATIONS.md#timeout-budget) |
| `RATE_LIMIT_DEFAULT_PER_MINUTE` | 300 | Default per-client bucket |
| `RATE_LIMIT_FORECAST_PER_MINUTE` | 30 | Forecast/export bucket (also the organisation data export) |
| `RATE_LIMIT_AUTH_PER_MINUTE` | 10 | Per-IP bucket shared by login, registration and password change |
| `RATE_LIMIT_ADMIN_PER_MINUTE` / `RATE_LIMIT_ADMIN_READ_PER_MINUTE` | 30 / 240 | Operator writes / operator reads (`GET`, `HEAD`) |
| `LOGIN_FAILURES_MAX` | 5 | Failed sign-ins per (e-mail, IP) before a pause (`scope=client`) |
| `LOGIN_ACCOUNT_FAILURES_MAX` | 100 | Failed sign-ins per e-mail from all IPs before a pause (`scope=account`) |
| `LOGIN_FAILURE_WINDOW_SECONDS` | 900 | Window for both counters |
| `API_INSTANCES` | 1 | Must be 1 (single-instance deployment) |
| `AUDIT_RETENTION_DAYS` | 0 | Period used by `icp-api audit-prune` (0 = keep everything; pruning is never automatic) |
| `PUBLIC_HISTORY_MONTHS` | 24 | Months of official ICP and Brent history in the public market snapshot (`recent`); allowed 0-36, validated at start-up (any env); `0` disables the public history |

Monthly API-key quotas come from the plan (`api_requests_per_month` in `entitlements.py`), not from the environment.

## Identity, e-mail and billing settings (backend)

Names and defaults only; values of the secret ones never go into files in the repository.

| Variable | Default | Meaning |
|---|---|---|
| `SESSION_IDLE_TIMEOUT_HOURS` | 168 | A member session unused for this long is revoked server-side (on top of the absolute 30-day expiry); `0` disables the idle timeout |
| `TEMP_PASSWORD_TTL_HOURS` | 72 | Lifetime of a temporary password from an invitation or admin reset (allowed 1–720) |
| `EMAIL_ENABLED` | `false` | E-mail flows (password reset, verification, invitation e-mail). **`true` is refused at start-up** until an e-mail provider is integrated; while `false` those endpoints answer `503 EMAIL_DISABLED` |
| `EMAIL_LINK_BASE_URL` | empty | Origin used in e-mail links (`/verifikasi-email`, `/atur-ulang-sandi`, `/terima-undangan`) once e-mail exists |
| `BILLING_ENABLED` | `false` | Billing API (`/api/v1/billing/*`, including the Midtrans webhook); while `false` every billing endpoint answers `503 BILLING_DISABLED` |
| `MIDTRANS_ENVIRONMENT` | `sandbox` | Only `sandbox` is accepted; `production` is refused (billing then answers `503 BILLING_MISCONFIGURED`) |
| `MIDTRANS_SERVER_KEY` | empty | **Secret.** Midtrans server key for the configured environment; required when billing is enabled (sandbox keys are expected to start with `SB-Mid-server-`, an unverified convention, see [BILLING.md](BILLING.md)) |
| `MIDTRANS_CLIENT_KEY` | empty | Midtrans client key (not used by the API today; reserved for a Snap front end) |
| `MIDTRANS_TIMEOUT_SECONDS` | 15 | Timeout of calls to the Midtrans Snap and status APIs |

Billing settings are read in `backend/icp_api/billing/config.py` (not in `settings.py`).

## Gateway Worker variables

| Name | Kind | Notes |
|---|---|---|
| `BACKEND_URL` | var (per env in `wrangler.jsonc`) | backend URL; staging: the Vercel production domain (one line, set after the first backend deploy); the Quick Tunnel fallback passes the tunnel URL with `wrangler deploy --var` |
| `GATEWAY_SHARED_SECRET` | **secret** | `wrangler secret put GATEWAY_SHARED_SECRET --env <env>`; local: `apps/gateway/.dev.vars`; also authenticates `/api/internal/*`; always used for calls to the backend |
| `GATEWAY_ACCEPTED_SECRETS` | **secret**, optional | previous secret(s), comma-separated, accepted on `/api/internal/*` during a rotation only ([OPERATIONS.md](OPERATIONS.md#rotating-the-gateway-shared-secret)); delete it when the rotation is complete |
| `MAX_BODY_BYTES`, `UPSTREAM_TIMEOUT_MS`, `ENVIRONMENT` | var | defaults 2000000 / 30000 (90000 for deployed envs: slow or waking backends) |
| `PUBLIC_UPSTREAM_TIMEOUT_MS` | var | default 8000 (set to 8000 in every environment of `wrangler.jsonc`): upstream timeout for the anonymous `GET /api/v1/public/market-snapshot` and `GET /api/v1/plans`, after which the last-known-good copy is served (below the browser's 10 s public timeout). A missing or malformed value falls back to the default |
| `API_RATE_LIMITER`, `FORECAST_RATE_LIMITER` | rate-limit bindings | 300/min and 20/min per client key (internal routes are exempt) |
| `DB` | D1 binding | application metadata, served to the backend via `POST /api/internal/d1/query` |
| `OBJECTS` | KV binding | objects, served via `GET/HEAD/PUT /api/internal/objects/<key>`; the Worker also keeps its last-known-good public copies there under `edge-cache/` (refused by the data plane) |

Worker settings that are not variables: `assets.run_worker_first` (`/api/*` and pages run the Worker; `/assets`,
`/brand`, `/fonts`, `/img` and `/favicon.svg` are served directly; a new top-level folder in `apps/web/public` must
be added there, `test/resilience.test.ts` fails until it is) and, for staging only, the Cron Trigger
`17 22 * * *` (daily refresh of the two public copies).

## Serverless process (Vercel)

`icp_api.serverless` builds the app with `load_settings(serverless=True)`; the flag is set by that entry
point only, never read from the environment. Compared with a container process:

| Setting / behaviour | Serverless (Vercel) | Container (`icp-api serve`) |
|---|---|---|
| `API_HOST` rule | not applied (nothing binds a socket) | required non-loopback when deployed |
| Writable defaults (`SQLITE_PATH`, `LOCAL_OBJECT_DIR`, `SOURCE_CACHE_DIR`, `SOURCE_STATE_DIR`, MLflow defaults) | under `<temp dir>/icp` (`/tmp/icp`); explicit values still win | under `var/` |
| Library caches (`MPLCONFIGDIR`, `XDG_CACHE_HOME`, `XDG_CONFIG_HOME`) | set to `/tmp/icp/...` unless given | library defaults |
| Background jobs | none: `POST /api/v1/jobs` answers `503 JOBS_DISABLED`; ingestion runs on the operator machine | in-process runner |
| Local store bootstrap (migrations, seeds) | when the app is built, local stores only (deployed stores: never) | in the lifespan, local stores only |
| Production-model warm-up | started when the app is built (idempotent; the lifespan's start reuses it) | started in the lifespan |
| Python | 3.12 (`infra/vercel/.python-version`), dependencies `infra/vercel/requirements.txt` (no MLflow) | 3.11 image / 3.10 dev |
| Dependencies at start-up | 356 MB, above the 225 MiB Vercel keeps inside a function: by default Vercel installs them from PyPI into `/tmp/_vc_deps` at every cold start; `scripts/vercel-backend.mjs --deploy --bundle full` keeps them all inside (large functions, beta). See [DEPLOYMENT.md](DEPLOYMENT.md#size-of-the-function-measured-2026-10-27-and-how-vercel-packs-it) | installed in the image |
